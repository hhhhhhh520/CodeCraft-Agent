# 子页面上 Streamlit 健康检查请求 404

> 创建时间: 2026-09-12 | 状态: 🔴未解决（低优先级，不影响功能）

## 问题描述

访问非根路径的页面时，前端会向**错误的 URL** 请求 Streamlit 的两个内部端点，返回 404：

| 页面 | 404 的请求 |
|---|---|
| `/`（主页） | 无 |
| `/chat` | `/chat/_stcore/health`、`/chat/_stcore/host-config` |
| `/history` | `/history/_stcore/health`、`/history/_stcore/host-config` |
| `/settings` | `/settings/_stcore/health`、`/settings/_stcore/host-config` |

正确路径应是 `/_stcore/health` 与 `/_stcore/host-config`（无页面前缀）。

**影响**：子页面上「服务端重启检测」失效——前端拿不到健康响应，就无法感知后端已重启并提示用户。**页面本身功能不受影响**（四个页面实测均正常渲染、无异常块）。

## 出现原因

Streamlit 前端的健康检查用**相对路径**发起请求，浏览器按当前页面路径解析：

- 在 `/` → `_stcore/health` 解析为 `/_stcore/health` ✅
- 在 `/settings` → 解析为 `/settings/_stcore/health` ❌

属 Streamlit 多页面路由的既有行为，与本项目的业务代码无关。

**已用对照实验确认非本轮引入**：把仓库回退到 HEAD（`6d8c7d7` 前）重跑同样的浏览器检测，`/settings` 页的 404 请求**完全一致**，页面文本长度也一致（535 字符）。

## 解决方案（未实施）

三条路，均未验证：

1. **不处理**——影响面是"重启提示不弹"，用户刷新页面即可，性价比最低优先
2. **升级 Streamlit**——先查该问题在新版本是否已修（`pip index versions streamlit` 对比 1.55.0）
3. **绕开多页面路由**——改用单入口 + 侧栏自绘导航，让 URL 始终停在 `/`。改动大，不值当

## 验证方式

若实施修复，复测方法：真启动应用 → 逐页访问 → 用 Playwright 监听 `response` 事件，断言 `status >= 400` 的请求数为 0。

参考本次的检测脚本思路：`page.on('response', r => r.status() >= 400 && ...)`。
