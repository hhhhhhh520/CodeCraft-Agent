# 依赖版本漂移问题记录

> 创建时间: 2026-04-22
> 状态: 🟢 已解决

## 问题描述

项目在共享虚拟环境中测试通过，但创建独立虚拟环境后出现依赖冲突和测试失败。

## 出现原因

### 根本原因：共享虚拟环境导致依赖版本漂移

1. **共享环境**：多个项目共用 `D:\python\project\.venv`
2. **隐式依赖升级**：其他项目安装包时，间接升级了共享环境中的依赖
3. **版本不锁定**：`requirements.txt` 只指定直接依赖，未锁定间接依赖版本

### 具体问题

| 问题 | 原因 |
|------|------|
| `np.float_` 移除错误 | ChromaDB 0.4.x 使用 `np.float_`，NumPy 2.0 已移除 |
| typer 版本冲突 | typer 0.24.x 需要 click 8.2.x，环境中是 click 8.1.x |

## 解决方案

1. 创建独立虚拟环境 `.venv`
2. 锁定 numpy 版本：`numpy>=1.24.0,<2.0.0`
3. 放宽其他依赖版本范围

## 预防措施

- 每个项目使用独立 `.venv`
- 使用 `pip-compile` 锁定所有依赖
- CI/CD 中验证独立环境
